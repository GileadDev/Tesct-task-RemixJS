## 2. Пошаговая установка

Перед стартом два нюанса PowerShell:

- В Windows PowerShell 5.1 нет оператора `&&`. Выполняйте команды по одной строке или через `;`.
- Если `npm`/`npx` пишет «running scripts is disabled on this system», один раз выполните:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Документация: ⭐ [about_Execution_Policies](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies).

### Шаг 5. Prettier и его дружба с ESLint

```powershell
npm install --save-dev --save-exact prettier
npm install -D eslint-config-prettier prettier-plugin-tailwindcss
```

Создайте в корне проекта файл `.prettierrc`:

```json
{
  "semi": true,
  "singleQuote": false,
  "plugins": ["prettier-plugin-tailwindcss"],
  "tailwindStylesheet": "./app/globals.css",
  "tailwindFunctions": ["cn", "cva"]
}
```

Если выбрали `src/`, путь будет `./src/app/globals.css`. Плагин Tailwind должен быть **последним** в `plugins`.

Файл `.prettierignore`:

```
.next
build
coverage
node_modules
```

Откройте `eslint.config.mjs` и добавьте Prettier ровно так, как показано в разделе «With Prettier» официальной страницы (ссылка ниже): `import prettier from "eslint-config-prettier/flat"` и элемент `prettier` в массиве **после** `...nextVitals` и `...nextTs`, но **до** `globalIgnores`.

В `package.json` в `scripts` добавьте к существующим:

```json
"lint:fix": "eslint --fix",
"format": "prettier . --write",
"format:check": "prettier . --check"
```

Это фрагмент для объекта `scripts`: поставьте запятую после предыдущей строки (`"lint": "eslint",`). Если `lint:fix` в сгенерированном `package.json` уже есть, не дублируйте ключ, добавьте только `format` и `format:check`.

Создайте `.vscode/settings.json`:

```json
{
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": { "source.fixAll.eslint": "explicit" }
}
```

Проверка: `npm run format`, затем `npm run lint`.

### Шаг 7. MongoDB

Выберите один из трёх вариантов.

**Вариант A. MongoDB Atlas, бесплатный кластер M0.** Ничего не ставится, рекомендуется для тестового.

1. Зарегистрируйтесь: https://www.mongodb.com/cloud/atlas/register
2. Project Overview → Create → **M0 Free** → провайдер и ближайший регион → имя кластера (Cluster0) → Create.
3. В Security Quickstart: задайте username/password пользователя БД (сохраните пароль) → Create Database User → **Add My Current IP Address** → Finish and Close.
4. Clusters → Connect → **Drivers** → Node.js → скопируйте строку `mongodb+srv://<user>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`.
5. Подставьте пароль (спецсимволы `$ : / ? # [ ] @` кодируйте: `@` → `%40`, `$` → `%24`, `:` → `%3A`, `#` → `%23`) и добавьте имя базы перед `?`: `/form_builder?retryWrites=true&w=majority`.

Если сменили сеть и подключение отвалилось: Security → Database & Network Access (в старом интерфейсе Network Access) → вкладка IP Access List → Add Current IP Address.

**Вариант B. Локально, MongoDB Community Server 8.x.** Скачайте MSI, в мастере оставьте «Install MongoD as a Service» и галку «Install MongoDB Compass». Строка подключения: `mongodb://127.0.0.1:27017/form_builder` (именно `127.0.0.1`, не `localhost`, иначе на Windows будет `ECONNREFUSED ::1`). Проверить службу: `Get-Service MongoDB`.

**Вариант C. Docker.** Требует установленного Docker Desktop с WSL 2, см. шаг 11. Если Docker ещё не стоит, берите вариант A или B.

```powershell
docker run -d --name mongo -p 27017:27017 -v mongo_data:/data/db -e MONGO_INITDB_ROOT_USERNAME=root -e MONGO_INITDB_ROOT_PASSWORD=example mongo:8
```

Строка: `mongodb://root:example@127.0.0.1:27017/form_builder?authSource=admin`.

**Инструменты** (для любого варианта):

```powershell
winget install --id MongoDB.Shell -e
```

Затем в новом окне `mongosh '<ваша строка>'` и `show dbs`. В PowerShell строку берите в одинарные кавычки: в двойных символ `$` в пароле раскроется как переменная. GUI: [MongoDB Compass](https://www.mongodb.com/try/download/compass), подключается той же строкой. Compass нужен, чтобы глазами проверять коллекции после каждого шага CRUD.

### Шаг 8. Библиотеки проекта

```powershell
npm install mongoose zod react-hook-form @hookform/resolvers jose bcryptjs server-only
```

Что это: `mongoose` (ODM для MongoDB, типы встроены), `zod` (валидация, ставится 4.x), `react-hook-form` + `@hookform/resolvers` (формы + `zodResolver`), `jose` (подпись и проверка JWT), `bcryptjs` (хеш пароля админа, чистый JS без сборки), `server-only` (защита от случайного импорта серверного кода в клиент).

**Не ставьте** `@types/mongoose` и `@types/bcryptjs`: это устаревшие заглушки, типы уже внутри пакетов.

Для одноразового скрипта создания админа: `npm install -D tsx`, а в `package.json` → `scripts` добавьте `"seed:admin": "tsx --env-file=.env.local scripts/seed-admin.ts"`. Сам файл `scripts/seed-admin.ts` пишете по ссылкам блока «Создание единственного админа» в разделе 3.7: подключение через mongoose, upsert пользователя по `ADMIN_EMAIL`, хеш пароля через bcryptjs с cost 10, отключение; пароль не логировать. Запуск один раз после шага 9: `npm run seed:admin` (повторный запуск безопасен благодаря upsert). Альтернатива без tsx на Node 24: `node --env-file=.env.local scripts/seed-admin.ts`, но тогда в скрипте только «стираемый» синтаксис TS (без enum, декораторов, parameter properties).

Проверка: `npm ls mongoose zod jose react-hook-form @hookform/resolvers`. Ожидается mongoose 9.10.x, zod 4.6.x, jose 6.x, react-hook-form 7.8x, resolvers 5.9.x.

### Шаг 9. Переменные окружения

Сгенерируйте секрет для JWT (в PowerShell нет `openssl`, поэтому через Node):

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Создайте `.env.local` **в корне проекта** (не в `src/`):

```
MONGODB_URI=<строка из шага 7>
SESSION_SECRET=<сгенерированный секрет>
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=<пароль, который скрипт захеширует>
```

Переменные без префикса `NEXT_PUBLIC_` доступны только на сервере, так и должно быть. `.env.local` уже в `.gitignore`.

Создайте `.env.example` с теми же ключами без значений, чтобы проверяющий видел, что нужно. Шаблон `.gitignore` игнорирует `.env*` целиком, поэтому допишите в `.gitignore` строку `!.env.example`.

Если после правки `.env.local` значение не подхватилось, перезапустите `npm run dev`.

Что сделать в проекте (по официальным примерам, ссылки ниже):

1. В `next.config.ts` включить `output: "standalone"`.
2. Скопировать `Dockerfile` и `.dockerignore` из официального примера `with-docker` (трёхстадийная сборка deps → builder → runner, базовый образ `node:24.13.0-slim`, non-root пользователь `node`, `CMD ["node","server.js"]`).
3. Написать `compose.yaml` с двумя сервисами: `mongo` (образ `mongo:8`, **именованный том** на `/data/db`, порт `27017:27017`, переменные `MONGO_INITDB_ROOT_USERNAME/PASSWORD`, `healthcheck`) и `app` (`build: .`, порт 3000, `MONGODB_URI` и `SESSION_SECRET` через `environment`, `depends_on` с `condition: service_healthy`, иначе приложение может стартовать раньше базы). Ключ `version:` в начале файла больше не нужен.
4. Внутри сети compose хост базы = имя сервиса `mongo`, а не `127.0.0.1`, и нужен `?authSource=admin`.
5. Seed админа при запуске через compose: образ standalone не содержит `scripts/` и tsx, поэтому скрипт запускают с хоста. После `docker compose up --build` во втором окне выполните `npm run seed:admin`, при этом `MONGODB_URI` в `.env.local` должен указывать на контейнер: `mongodb://root:example@127.0.0.1:27017/form_builder?authSource=admin`. Оба действия опишите в README рядом с `docker compose up --build`.


`next build` в Next 16 больше не запускает ESLint, поэтому `npm run lint` нужно запускать самому. `next typegen` создаёт `next-env.d.ts` и глобальные типы `PageProps`/`LayoutProps`/`RouteContext` без полной сборки; без него `tsc --noEmit` на чистом клоне падает, потому что `next-env.d.ts` в `.gitignore`. ### 3.14 Тестирование REST API: cookie, 401, тело запроса

Рекомендация: расширение REST Client для VS Code и файл `api.http` в корне репозитория. Он текстовый, коммитится вместе с проектом, служит живой документацией API для проверяющего и хранит cookie между запросами (настройка `rest-client.rememberCookiesForSubsequentRequests` включена по умолчанию).

```powershell
code --install-extension humao.rest-client
```

Как устроен файл: сверху переменные вида `@baseUrl = http://localhost:3000`; запросы разделяются строкой `###`; заголовки идут сразу под строкой запроса без пустой строки; ровно одна пустая строка перед телом; `# @name createForm` над запросом позволяет потом брать значения из его ответа, например `{{createForm.response.body.$.id}}` (ваш DTO отдаёт `id`, а не `_id`; `$._id` нужен, только если API возвращает сырой документ Mongoose); `# @no-cookie-jar` над запросом отправляет его без cookie, так делается проверка на 401. Отправка: курсор внутри запроса, Ctrl+Alt+R, ответ открывается справа со статусом и заголовками. Сценарий, который стоит записать в файл: логин → список → создание (201) → чтение по id → обновление → тот же PUT с `# @no-cookie-jar` (401) → удаление (204) → логаут → создание после логаута (401). Пароль держите в файле `.env` рядом с `api.http` (REST Client читает только `.env`, не `.env.local`, поэтому `ADMIN_PASSWORD` придётся продублировать; `.env` уже под `.gitignore`) и подставляйте через `{{$dotenv ADMIN_PASSWORD}}`. Cookie-jar лежит в `%USERPROFILE%\.rest-client\cookie.json` и переживает перезапуск VS Code: если после истечения JWT всё стало отвечать 401, повторите запрос логина или выполните команду палитры «Rest Client: Clear cookies».

Главная ловушка: cookie с флагом `Secure` по `http://localhost` браузеры и `curl.exe` отправляют, а REST Client и Postman нет. Поэтому в login-роуте ставьте `secure: process.env.NODE_ENV === 'production'` (официальный гайд жёстко пишет `secure: true`), иначе все admin-запросы из REST-клиента будут возвращать 401 без видимой причины.

Другие инструменты:

- Thunder Client: удобный GUI, но с августа 2025 коллекции платные, а бесплатная версия требует логина; для одиночных запросов подходит, cookie видны во вкладке Cookies → Manage Cookies.
- Postman: не поддерживает SameSite, `Secure`-cookie по http не отправляет, веб-версии нужен Desktop Agent для localhost. Установка: `winget install --id Postman.Postman -e --source winget`.
- PowerShell 5.1: `Invoke-RestMethod` с `-SessionVariable`/`-WebSession` (примеры в этапах 3–4 раздела 5); 401 бросает исключение, ловите через `try/catch`; для кириллицы в теле `-ContentType 'application/json; charset=utf-8'`; без `-ContentType` POST уходит как form-urlencoded. `curl` в PowerShell — это алиас Invoke-WebRequest, настоящий curl вызывается как `curl.exe` (`-c cookies.txt` сохраняет cookie после ответа, `-b cookies.txt` отправляет их, `-i` показывает заголовки).
- Браузер: DevTools → Network → запрос логина → Response Headers → строка `Set-Cookie`; Application → Cookies → колонки HttpOnly, Secure, SameSite.

### 3.15 Деплой на Vercel (по желанию, плюс к сдаче)

Vercel Hobby + MongoDB Atlas Free бесплатны, а ссылка на живое демо в README сильно помогает проверяющему. Порядок:

1. В `package.json` добавьте `"engines": { "node": "24.x" }`: Node 20 на Vercel отключается для новых деплоев с 1 октября 2026.
2. Локально прогоните проверки из шага 13. `next build` на Vercel падает на любой ошибке TypeScript, а ESLint там не запускается.
3. `git config core.ignorecase false`. Windows не различает регистр в именах файлов, Linux-сборка Vercel различает: импорт `./button` при файле `Button.tsx` работает у вас и падает на Vercel с «Module not found». Если файл уже переименовывали только регистром, переименуйте через промежуточное имя двумя `git mv`.
4. Репозиторий должен быть под вашим личным аккаунтом GitHub: Hobby-команды не подключают репозитории организаций. Приватный подходит.
5. Atlas → Security → Database & Network Access (в старом интерфейсе Network Access) → вкладка IP Access List → Add IP Address → `0.0.0.0/0`, комментарий Vercel, не ставьте галку «temporary». Vercel ходит с динамических IP, статический только на платных планах. Компенсируйте сильным паролем пользователя БД с правами только на вашу базу.
6. Сгенерируйте отдельный `SESSION_SECRET` для продакшена той же командой из шага 9.
7. Откройте https://vercel.com/new, импортируйте репозиторий (при первом разе установите GitHub App на выбранные репозитории). Framework Preset определится как Next.js, Root Directory `./`, сборку не трогайте. В блоке Environment Variables добавьте `MONGODB_URI`, `SESSION_SECRET` и при бонусе `OPENAI_API_KEY` (можно вставить содержимое `.env`-файла целиком), затем Deploy. Первый деплой всегда production.
8. После любого изменения env-переменных: Deployments → ⋯ → Redeploy. Уже собранный деплой новых значений не видит.
9. Settings → Build and Deployment → Node.js Version 24.x. `proxy.ts` разворачивается как Routing Middleware автоматически, никаких флагов не нужно.
10. Seed админа в Atlas с вашей машины. Строку подключения вводите через `Read-Host`, а не в самой команде: PSReadLine по умолчанию пишет каждую введённую строку в `%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\ConsoleHost_history.txt`, и пароль остался бы в истории. Переменная `$env:` живёт только в этой сессии и имеет приоритет над `.env.local`:

```powershell
$env:MONGODB_URI = Read-Host 'Строка подключения Atlas'; npm run seed:admin; Remove-Item Env:\MONGODB_URI
```

11. Проверка по `https://<project>.vercel.app`: главная, логин, в DevTools у cookie стоят HttpOnly и Secure, создание формы, публичная страница, модалка. Ошибки: Project → Logs, фильтр Level = Error; Hobby хранит логи один час.
12. Preview-деплои для веток и PR могут быть закрыты Vercel Authentication: проверяющему давайте production-домен `<project>.vercel.app`.
13. В README раздел Deployment: ссылка на демо, хостинг (Vercel Hobby + Atlas Free), таблица env-переменных без значений, напоминание «после смены env → Redeploy», команда seed.

Ловушки: `MongooseError: buffering timed out` на Vercel почти всегда означает неверный или отсутствующий `MONGODB_URI` (проверьте имя ключа и галку Production); Atlas Free засыпает после 30 дней без обращений и до ручного Resume не принимает подключений (сайт его не разбудит, а покажет ошибку): перед собеседованием нажмите Resume в консоли Atlas, а чтобы кластер не заснул, открывайте сайт хотя бы раз в неделю; переменные с префиксом `NEXT_PUBLIC_` вшиваются в бандл при сборке и видны в браузере; интеграция Atlas из Vercel Marketplace создаёт новый кластер, а не подключает ваш существующий, поэтому seed придётся повторить.

## 4. Главные ловушки

Здесь то, что чаще всего ломает код из уроков 2024–2025 годов.

**Next.js 16**

- `middleware.ts` → `proxy.ts`, функция называется `proxy`. Работает только на Node runtime. Кодмод: `npx @next/codemod@canary middleware-to-proxy .`
- `params`, `searchParams`, `cookies()`, `headers()` только через `await`. Синхронный доступ удалён. Кодмод: `npx @next/codemod@canary next-async-request-api .`
- `next lint` удалён, `next build` не линтит. Скрипт `"lint": "eslint"`.
- Turbopack по умолчанию; кастомный `webpack`-конфиг в `next.config` ломает сборку.
- GET Route Handlers не кэшируются по умолчанию (с v15), `force-dynamic` добавлять не нужно.
- Не делайте `fetch('http://localhost:3000/api/...')` из Server Components: читайте базу напрямую через функции в `lib/`. REST нужен браузеру (клиентские компоненты) и внешним клиентам.
- `route.ts` и `page.tsx` не могут лежать в одной папке. API держите под `app/api/**`.
- `error.tsx` в 16.3 получает `retry`, а не только `reset`.
- Установщик по умолчанию добавляет `AGENTS.md`/`CLAUDE.md`, отвечайте No.
- `fetch()` не бросает исключение на 400/401: проверяйте `res.ok` перед `router.push()`/`router.refresh()`, иначе неудачное сохранение выглядит успешным. `res.json()` на пустом теле (204) бросает исключение: возвращайте JSON или проверяйте статус.
- В обработчиках событий клиентских компонентов работает `useRouter`, а не `redirect()`. `refresh()` из `next/cache` работает только в Server Actions. После мутации через REST вызывайте `router.refresh()`: он перерисует Server Components, но не тронет состояние `useState`, поэтому список форм держите в Server Component, а не копируйте в state.
- В production публичная страница, которая читает базу без `cookies()`/`headers()`, пререндерится статически при `next build` и не увидит новых форм; в `next dev` этого не видно. Лечится `export const dynamic = 'force-dynamic'` на публичных страницах или `revalidatePath` в POST/PUT/DELETE-роутах. Проверяйте `npm run build; npm run start`.
- Matcher `/admin/:path*` ловит и `/admin/login`, получится цикл редиректов. Страницу логина держите на `/login`.
- Параметр `?from=` для возврата после логина принимайте только как путь, начинающийся с `/` и не с `//`, иначе открытый редирект. Клиентский компонент с `useSearchParams()` оборачивайте в `<Suspense>`, иначе `next build` упадёт с ошибкой «Missing Suspense boundary with useSearchParams».

**Zod 4**

- Параметры `required_error` и `invalid_type_error` **удалены**; есть единый `error` или короткая форма `z.string("сообщение")`. Официальный гайд Next.js по формам всё ещё показывает старый вариант.
- `.format()`/`.flatten()` помечены устаревшими: работают и удаляться не будут, но новый код пишите через `z.flattenError()` и `z.treeifyError()`. Вместо `error.errors` читайте `error.issues`.
- `z.string().email()` → `z.email()`; `.merge()` → `.extend()`; `z.record()` требует два аргумента; `z.nativeEnum` → `z.enum`.
- HTML-инпуты отдают строки: для числовых полей `z.coerce.number()` или `valueAsNumber`; пустую строку в необязательном поле переводите в `undefined`.
- Схема из полей формы строится дорого, оборачивайте в `useMemo`.
- Для необязательных чисел не `z.coerce.number()`, а `z.preprocess` (`''` и `NaN` → `undefined`) перед `z.number()`: `Number('')` равно 0, и пустое поле молча пройдёт как ноль.
- `.multipleOf(step)` считает от нуля, а браузерный атрибут `step` от `min`: при `min=1, step=2` браузер примет 3, Zod отвергнет. Выберите одно правило (например `.refine`, проверяющий, что `(value - (min ?? 0)) / step` — целое число с допуском на погрешность float: для дробного `step` вроде 0.1 оператор `%` даёт 0.0999…, а не 0) и опишите его в README.
- `z.strictObject` вместо `z.object` для тела запроса: лишний ключ или опечатка вроде `minlength` даст 400, а не будет молча отброшена Mongoose.

**Mongoose 9**

- Хуки `pre`/`post` только `async`, без `next()`. Колбэки убраны везде.
- Свойство поля с именем `type` объявляется как `type: { type: String, enum: [...] }`.
- Guard моделей `mongoose.models.Form || mongoose.model(...)` и кэш подключения на `globalThis`, иначе `OverwriteModelError` и утечка соединений при hot reload.
- `.lean()` и приведение `_id` к строке перед передачей в Client Components.
- `{ new: true }` → `{ returnDocument: 'after' }`; валидация при update только с `{ runValidators: true }`.
- На Windows `localhost` → `127.0.0.1`.
- Mongoose не работает в Edge runtime и не должен вызываться из `proxy.ts`.
- `mongoose.isValidObjectId('hello-world!')` возвращает true для любой 12-символьной строки. Для id из URL используйте `isObjectIdOrHexString` и отвечайте 404 до запроса в базу.
- У субдокументов полей ставьте `_id: false` и храните свой строковый `id`, иначе при каждом PUT Mongoose выдаст новый `_id` каждому полю, пришедшему без `_id`, и выбранное в редакторе поле «потеряется» после сохранения.
- Обновление через `findByIdAndUpdate` без `runValidators: true` вообще не проверяет `enum` и `required` схемы.

**JWT**

- `jose`, а не `jsonwebtoken`. Секрет в байты через `TextEncoder`, `algorithms: ['HS256']` в `jwtVerify`.
- `jwtVerify` бросает исключение на просроченном токене, оборачивайте в `try/catch`.
- Cookie ставится и удаляется только в Route Handlers и Server Functions, не при рендере страницы. Logout через POST.
- `proxy.ts` не единственная защита (CVE-2025-29927): `verifySession()` в каждом admin-роуте и на каждой admin-странице.
- `verifySession()` из официального гайда редиректит на `/login`; для Route Handlers нужен вариант без редиректа, который возвращает `null`, чтобы API отвечал 401, а не 307. В сниппете гайда пропущены импорты `cache` из `react` и `redirect` из `next/navigation`.
- Токен только в httpOnly cookie, никогда в localStorage.
- `secure: true` в браузере на localhost работает, но `Invoke-RestMethod` из PowerShell такую cookie не отправит по http. Для теста из PowerShell `secure: process.env.NODE_ENV === 'production'`.
- `redirect()` не внутри `try/catch`.

**Tailwind 4 и shadcn**

- Нет `tailwind.config.js`, нет `@tailwind base/components/utilities`. Всё через `@import "tailwindcss"` и `@theme`.
- Переименования утилит: `shadow-sm` → `shadow-xs`, `rounded` → `rounded-sm`, `outline-none` → `outline-hidden`, `ring` → `ring-3`.
- Пакет `shadcn`, не `shadcn-ui`. Флагов `--style`, `--base-color`, `--src-dir` у `init` больше нет.
- Base UI вместо Radix: `asChild` → `render`, `data-[state=open]` → `data-open`. Не смешивайте компоненты из Radix-уроков с Base UI-проектом. Для ссылки-кнопки `buttonVariants()` + `<Link>`.
- Старый `Form/FormField/FormItem` → `Field/FieldLabel/FieldError` + `Controller`.
- `prettier-plugin-tailwindcss` для Tailwind v4 требует опцию `tailwindStylesheet` с путём к вашему CSS-входу, иначе плагин не видит тему и кастомные утилиты.

**react-hook-form, редактор и публичная форма**

- `useFieldArray` перезаписывает свойство `id` у ваших объектов своим ключом. Задайте `keyName: 'rhfId'` (опция помечена к удалению в RHF 8, поэтому вариант с другим именем свойства для id поля надёжнее) и используйте `key={field.rhfId}`, никогда индекс. `shouldUnregister: true` с массивами не работает.
- `fields` из `useFieldArray` — это снимок для ключей; живые значения для превью читайте через `useWatch`. `watch()` в корне перерисовывает всё приложение.
- Выбранное поле храните по ключу, а не по индексу: после `remove`/`move` индексы сдвигаются. Смена типа поля через `update(index, объект с дефолтами нового типа)`, иначе останутся опции старого типа.
- `noValidate` на `<form>`, иначе браузер показывает свои пузыри вместо ошибок Zod. Атрибут `maxLength` на инпуты не вешайте вовсе: он не даёт напечатать лишнее независимо от `noValidate`, и сообщение Zod о лимите никогда не покажется.
- У каждого поля публичной формы должно быть значение `''` в `defaultValues` (и у числовых), иначе предупреждение «uncontrolled → controlled». `Controller.onChange(undefined)` недопустим, отправляйте `null` или `''`.
- Dialog подтверждения рендерите рядом с `<form>`, а не внутри: события порталов всплывают по дереву React и могут повторно вызвать submit. Кнопкам внутри модалки ставьте `type="button"`.
- Превью в редакторе: `readOnly` + `pointer-events-none` на инпуте и `onClick` на обёртке поля; `<fieldset disabled>` глотает клики.
- Не сбрасывайте форму сайдбара через `useEffect` при смене выбранного поля: сначала отрисуются старые значения. Перемонтируйте её через `key`.

**REST-клиенты и Vercel**

- REST Client и Postman не отправляют `Secure`-cookie по `http://localhost`, браузеры и `curl.exe` отправляют. Отсюда `secure: process.env.NODE_ENV === 'production'`.
- В PowerShell `curl` — это алиас Invoke-WebRequest, настоящий вызывается как `curl.exe`. `Invoke-RestMethod` без `-ContentType` отправляет POST как `application/x-www-form-urlencoded`; `request.json()` в Route Handler разбирает тело как текст и на JSON-строке не упадёт, но тип указывайте явно, а для кириллицы обязательно `-ContentType 'application/json; charset=utf-8'`, иначе тело уйдёт в ASCII.
- Vercel: изменение env-переменных не применяется к текущему деплою, нужен Redeploy. Windows не различает регистр имён файлов, Linux-сборка различает: `git config core.ignorecase false`. Atlas без `0.0.0.0/0` даёт таймауты только на Vercel. Atlas Free засыпает через 30 дней простоя.

## 5. Порядок изучения и сборки

**Этап 0. Основы (если App Router в новинку).** ⭐ React Foundations → ⭐ Learn Next.js главы 1–9 и 14 (или TeaCoder / Минин на русском). Параллельно ⭐ Zod basics и ⭐ Mongoose Getting Started.

**Этап 1. Установка.** Шаги 1–10 раздела 2. Коммит «project setup», push.

**Этап 2. Модель данных.** Читать: Mongoose Schemas, SchemaTypes («The type Key»), Subdocuments; Zod discriminated unions. Решить: `Form` (title, description, published, fields[]), `Field` = discriminated union по `type` ровно с опциями из задания: общие для всех `label`, `placeholder`, `required`; `text` — `minLength`, `maxLength`; `number` — `min`, `max`, `step`; `textarea` — `minLength`, `maxLength`, `rows`. Лишних типов и опций не добавляйте, проверяют именно этот набор. У каждого поля свой стабильный `id` (нужен для выбора поля в редакторе и как `name` инпута в публичной форме). Одна Zod-схема поля в `lib/validation`, без серверных импортов, чтобы использовать и на клиенте, и в API. Модель Mongoose с guard'ом и `lib/dbConnect.ts` по образцу Vercel. Хранение полей, два рабочих варианта: (1) одна схема поля-субдокумента с `type: { type: String, enum: ['text','number','textarea'] }` и всеми опциями как optional, а правило «какие опции у какого типа» проверяет Zod на входе в API; (2) embedded discriminators в массиве с `discriminatorKey: 'type'` (хуки объявлять до `discriminator()`). Для тестового с дедлайном достаточно варианта 1. Проверить подключение через mongosh или Compass.

Контракт данных, решите заранее и запишите в README: (1) у каждого поля строковый `id`, сгенерированный на клиенте через `crypto.randomUUID()` в момент добавления (`localhost` — безопасный контекст, функция доступна), у субдокумента `_id: false`; при сохранении редактор возвращает существующие `id`, сервер их никогда не перегенерирует; (2) порядок в массиве `fields` равен порядку отображения, отдельного поля `order` нет; (3) `published` булево на форме с индексом, публичный список фильтрует по нему; (4) Zod-схема формы через `z.strictObject` (лишние ключи дают 400) с `.refine` на уникальность `id` и на правило «нельзя опубликовать форму без полей»; (5) сериализатор в `lib/`, который превращает документ или lean-объект в DTO со строковым `id` и ISO-датами, потому что `.lean()` оставляет `_id` объектом ObjectId, а React не пропускает экземпляры классов в Client Components; (6) что происходит после модалки подтверждения: вариант A сохранять ответы (`POST /api/forms/[id]/submissions`, коллекция `submissions`, `values` как объект «id поля → значение») или вариант B только показать модалку. Задание требует только модалку, вариант A небольшой бонус.

**Этап 3. REST API.** Читать: Route Handlers, route.js, BFF guide, статья Makerkit. Таблица эндпоинтов (все admin-эндпоинты `/api/forms*` требуют cookie админа, без неё 401; исключение — публичный `POST …/submissions` из варианта A):

| Метод и путь | Тело | Ответ |
|---|---|---|
| `GET /api/forms` | нет | 200, массив DTO, включая черновики |
| `POST /api/forms` | форма | 201 + DTO + заголовок `Location`; 400 при ошибке Zod или битом JSON |
| `GET /api/forms/[id]` | нет | 200 DTO; 404 если id не 24-hex или документа нет |
| `PUT /api/forms/[id]` | форма целиком: `title`, `description`, `published`, `fields` | 200 DTO; 400; 404. Массив `fields` заменяется целиком |
| `DELETE /api/forms/[id]` | нет | 204 без тела; 404 |
| `PATCH /api/forms/[id]` (по желанию) | `{ published }` | 200 DTO, переключение публикации без пересылки полей |
| `POST /api/forms/[id]/submissions` (вариант A) | `{ values }` | публичный; 201; 400; 404 если форма не опубликована |

Правила: `await request.json()` бросает исключение на невалидном JSON, ловите и отвечайте 400; тело валидировать через `safeParse`, при ошибке 400 с `z.flattenError`; id из URL проверять через `mongoose.isObjectIdOrHexString`, иначе 404 ещё до запроса в базу; обновление через `findByIdAndUpdate` с `$set` и опциями `{ returnDocument: 'after', runValidators: true }`; остальные ошибки — 500 с записью в лог. Методы, которых нет в файле, Next.js сам отклоняет с 405. Проверять через REST Client и файл `api.http` (раздел 3.14), Compass, либо прямо из PowerShell:

```powershell
# список
Invoke-RestMethod http://localhost:3000/api/forms
# создание с JSON-телом
Invoke-RestMethod -Method Post -Uri http://localhost:3000/api/forms -ContentType 'application/json' -Body '{"title":"Test","fields":[]}'
```

Документация: ⭐ [Invoke-RestMethod](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/invoke-restmethod) (`-Method`, `-Body`, `-ContentType`, `-SessionVariable`, `-WebSession`). Коммит.

**Этап 4. Авторизация.** Читать целиком ⭐ Next.js Authentication guide, затем видео leerob. Сделать: `session.ts` (jose), `dal.ts` (`verifySession`), `POST /api/auth/login` и `logout`, `proxy.ts` с matcher на `/admin/:path*` (страницу логина держите вне `/admin`, например на `/login`, иначе получите цикл редиректов), seed-скрипт единственного админа (`npm run seed:admin`, см. шаг 8), защита всех `/api/forms*`. Нюанс: `verifySession()` из официального гайда делает редирект на `/login`, что для JSON-API неправильно (клиент получит 307 вместо 401), поэтому для Route Handlers сделайте вариант без редиректа, который возвращает `null`, и отвечайте 401. Публичной части REST не нужен, она читает базу напрямую (см. этап 6); если всё же оставляете публичный GET, отдавайте только формы с `published: true`. Проверить: в DevTools → Application → Cookies у `session` стоят HttpOnly, Secure, SameSite=Lax, Path=/; `/admin` без cookie → редирект на `/login`; `GET /api/forms` без cookie → 401; `POST /api/auth/logout` → cookie удалена и `/admin` снова редиректит. Из PowerShell защищённые эндпоинты проверяют так: логин с сохранением cookie в сессию, затем запросы с этой сессией:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:3000/api/auth/login -ContentType 'application/json' -Body '{"email":"admin@example.com","password":"..."}' -SessionVariable s
Invoke-RestMethod -Uri http://localhost:3000/api/forms -WebSession $s
```

Cookie с флагом Secure PowerShell по http не отправит: на время локальных тестов `secure: process.env.NODE_ENV === 'production'` (см. раздел 4) либо проверяйте из браузера через DevTools → Network. Страница логина: клиентский компонент делает `fetch` на login, проверяет `res.ok`, затем `router.push('/admin')` и `router.refresh()`; `redirect()` из `next/navigation` в обработчиках событий не работает. Кнопка выхода: POST на logout, затем `router.push('/login')` и `router.refresh()`. Параметр `?from=` для возврата после логина принимайте только как путь, начинающийся с `/` и не с `//`. Если читаете его через `useSearchParams()`, оберните этот клиентский компонент в `<Suspense>` (или читайте `searchParams` в серверной `page.tsx` и передавайте значение пропсом), иначе `next build` упадёт с ошибкой «Missing Suspense boundary with useSearchParams». Коммит.

**Этап 5. Админка.** Страница логина на `/login` (shadcn `login-03` как образец, поток описан в этапе 4). Список форм: Server Component читает базу напрямую (`.lean()`, `_id` в строку) и рисует Table; кнопки «Создать» и «Удалить» — это маленькие клиентские компоненты, которые делают `fetch`, проверяют `res.ok` и вызывают `router.refresh()`, чтобы список перечитался без перезагрузки. Удаление через Dialog подтверждения. Создание: «Создать» делает `POST /api/forms` с пустой формой (`title` по умолчанию, `fields: []`, `published: false`) и переходит на `/admin/forms/[id]`; дальше редактор всегда сохраняет через `PUT /api/forms/[id]`.

Редактор, два варианта архитектуры. **Вариант A (рекомендуется):** одна форма `useForm` владеет всем редактором. `useFieldArray` на массиве `fields` (обязательно `keyName: 'rhfId'`, иначе RHF перезапишет ваш `id`); выбранное поле хранится как ключ, индекс вычисляется через `findIndex`; превью читает значения через `useWatch` и обновляется на каждое нажатие; клик по полю открывает Sheet, внутри которого `Controller` с именами вида `fields.${index}.label` на том же `control`, поэтому синхронизацию сайдбара и превью писать не нужно; смена типа поля делает `update(index, объект с дефолтами нового типа)`, чтобы исчезли опции старого; удаление `remove(index)` плюс сброс выбора; порядок кнопками вверх/вниз через `move`. Кнопка «Сохранить» — это `handleSubmit`: валидирует всю форму по общей Zod-схеме, делает один PUT, затем `form.reset(data)` и toast. **Вариант B:** состояние редактора в `useReducer` (actions added, changed, deleted, moved, selected), а сайдбар — отдельная маленькая форма, которую перемонтируют через `key` из id и типа поля при смене выбора (React docs: не сбрасывать через `useEffect`). Вариант B оправдан, если состоянием редактора будет управлять кто-то извне формы, например AI-агент из бонуса. Числовые опции `min`, `max`, `step`, `minLength`, `maxLength`: `Controller.onChange(undefined)` недопустим, отправляйте `null` или `''` и нормализуйте в схеме через `z.preprocess`. Образцы для чтения: hasanharman/form-builder и formscn (раздел 3.12). Коммит.

**Этап 6. Публичная часть.** Главная: Server Component читает опубликованные формы из БД и показывает Card-список со ссылками. `/forms/[id]`: `page.tsx` как Server Component читает форму функцией из `lib/` с `.lean()` и условием `published: true`, при отсутствии вызывает `notFound()` (добавьте `not-found.tsx`), приводит `_id` к строке и передаёт plain-объект пропсом в дочерний `'use client'`-компонент. Уже клиентский компонент строит Zod-схему из полей (`useMemo`, Zod discussions #1099/#3287, статья Kalhara Perera), рендерит через RHF + Field, после сабмита открывает управляемый Dialog с введёнными данными. Как опции задания превращаются в валидаторы и атрибуты (на `<form>` стоит `noValidate`, поэтому нативные `required`/`minLength`/`maxLength` на инпуты не вешаем: пользователь должен видеть сообщения Zod, а не пузыри браузера):

| Опция из задания | Zod-валидатор публичной формы | Атрибут инпута |
|---|---|---|
| `label` | нет | `<FieldLabel>` |
| `placeholder` | нет | `placeholder` |
| `required` | `true` — `.min(1)` для строк; `false` — `.optional()`, пустую строку переводить в `undefined` | только `aria-required` |
| `minLength` / `maxLength` (text, textarea) | `z.string().min(n).max(m)` | не передавать: нативный `maxlength` не даст напечатать лишнее и спрячет сообщение |
| `min` / `max` (number) | `z.number().min(a).max(b)` после `z.preprocess` (`''` и `NaN` → `undefined`) | `type="number"`, `min`, `max`, `inputMode="decimal"` |
| `step` (number) | `.multipleOf(step)`, но см. ловушку про базу отсчёта в разделе 4 | `step`; без сохранённого step ставьте `step="any"` |
| `rows` (textarea) | нет | `rows`, по умолчанию 3 |

Детали: `defaultValues` со значением `''` для каждого поля, включая числовые, иначе React предупреждает о переходе uncontrolled → controlled; схему и `defaultValues` строить через `useMemo`; после `handleSubmit` сохранить проверенные значения в состояние и открыть управляемый Dialog (`open={pending !== null}`), отрисованный рядом с `<form>`, а не внутри; кнопкам модалки `type="button"`; «Подтвердить» либо просто закрывает модалку и делает `form.reset()` (вариант B из этапа 2), либо шлёт POST на submissions (вариант A) и показывает toast. Тот же компонент-рендерер полей используйте в превью редактора в режиме «только просмотр» (`readOnly` + `pointer-events-none`, клик ловит обёртка), чтобы превью и публичная страница никогда не расходились. Тексты ошибок: `z.config(uk())` из `zod/locales` даёт технические формулировки, поэтому лучше явные `{ error: '…' }` на каждой проверке.

Проверка в production-режиме: `npm run build; npm run start`. Публичные страницы, которые читают базу без `cookies()`/`headers()`, при сборке пререндерятся статически и не увидят новых форм; в `next dev` это незаметно. Либо `export const dynamic = 'force-dynamic'` в `app/page.tsx` и `app/forms/[id]/page.tsx`, либо `revalidatePath('/')` и `revalidatePath('/forms/[id]', 'page')` в POST/PUT/DELETE-роутах. Если включите `cacheComponents: true` в `next.config.ts` (по умолчанию выключено), страницы и так динамические, а `export const dynamic` там запрещён: остаются только `revalidatePath`/`updateTag`. Коммит.
